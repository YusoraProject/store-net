# 开发与维护

## 当前阶段

本项目尚未部署，按空库首次启动维护。源码独立放在 StoreNet 内，不能依赖父目录 ChipsNet 或 gaowo 的运行环境。两个项目有相似代码，也不代表能共用数据库或门锁密钥。

## 初始化方式

普通业务模型位于 `backend/models.py`，门锁和区域模型位于 `backend/access_models.py`。首次启动由 `backend/initialize.py` 一起建表并创建初始角色、管理员，不导入测试账号、门店或余额。

初始化可以重复执行，不会覆盖已有密码或业务数据。包场功能允许的增量操作仅为：验证全部原表一致后补建 `venue_bookings`、`booking_settings`、`booking_details`、`booking_invitations`、`booking_sessions` 中缺少的表。其他缺表、字段不一致或关键唯一约束缺失仍会停止，不修改已有表。

开发中调整模型后，使用新的空库测试，并保留原文件。如果以后开始保存正式营业数据，先设计安全的数据变更流程，再改表结构，不能依靠自动建表更新字段。

## 关键业务约定

- 数据库金额保存为整数分，对外显示两位小数。计费改动必须同时检查舍入、日夜切分、跨天和封顶。
- 同一会员只有一条全局计时占用；同店换区只新增停留区间，不创建第二笔消费，也不立即扣款。
- 扣权益、写流水、关闭消费和释放占用必须在同一事务完成。任何一步失败，其他步骤也要回退。
- 新区发码确认前保留原区计时。结果未知不能当作失败，更不能直接重发。
- 门锁调用不能长时间占用数据库事务。授权续期和发码核对都通过数据库状态防止重复处理。
- 令牌、账号密码和开门密码不写日志；密文绑定门店与用途，不能跨店替换。
- 前端显示菜单只是便于使用，权限和店长归属必须由后端重新验证。

## 文案与注释

页面写给会员和店长看，优先说明发生了什么、接下来怎么办。例如“余额不足，请联系店长结账”，不直接展示上游英文错误。

注释用于解释业务限制、事务边界和异常处理，不逐行重复代码。接口字段、权限键和第三方协议保留原名；不要改写用户自己的昵称、门店名和历史备注。

## 日常检查

后端使用 `python -m compileall -q backend` 检查语法，使用 `python -m unittest discover -s backend/tests -v` 验证计费规则和相关接口；前端使用 `npm test`、`lint --no-fix` 和生产构建。具体命令见[本地运行与配置](本地运行与配置.md)。

前端另有 `npm test`，用于检查 Vue 2 样式编译兼容和按需组件是否齐全。基础组件在 `src/ui/base.js`，后台组件随仪表盘加载。新增组件时同时引入对应样式，不要改回整包加载。

`build/vue2-style-imports.js` 只把普通样式的无用默认导入改为副作用导入，保留 CSS Modules 和服务端注入。它用于兼容当前 Vue Loader 15，不是过滤警告；将来更换加载器时需重新验证是否还需要保留。

后端测试只连接临时数据库，通通锁请求使用模拟接口。不要为了测试方便填入正式凭据，也不要让测试清空本地的业务库。

提交源码、依赖锁文件、测试与说明文档。`.env`、数据库、上传文件、虚拟环境、前端依赖及构建产物不提交。

## 尚需验收

当前 CI 覆盖动态时段、节假日、特殊日期、旧价格快照、同区封顶累计、包场订金、邀请、免计费会话、权限及并发预约和收退款。旧版门锁测试已移除，当前测试不代替自动发码和授权续期的完整验收。跨进程共享限流、MySQL、HTTPS、备份恢复与真实门锁仍需进一步验收；当前代码和本地检查不代表已经上线。

## 可配置计费规则

规则存放在现有 `access_areas.pricing_json`，不修改数据库表结构。V2 对象包含时段、计费时区、周末/节假日开关与日期规则。接口价格单位为元，写入 JSON 后各费率使用 `hourly_cents`、`cap_cents` 整数分；读取只转换金额，不转换时间或布尔配置。

`backend/pricing.py` 统一校验及转换，`billing.charge_parts` 供普通计费和换区累计共用。旧快照继续按原时钟计算；当前配置及新计费段固定 UTC+8。仅格式转换且规则未变时，不重置同区封顶。规则会随上机、发码申请及换区保存快照，不从当前配置重新套用历史记录。

单区域门店的“定价”页与区域编辑共用 `PricingEditor`；多区域门店需分别编辑区域。详细业务语义见[计费规则配置](计费规则配置.md)。
