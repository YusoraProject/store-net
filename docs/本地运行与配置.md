# 本地运行与配置

当前项目按还未部署的状态准备。先在本机和空数据库中走通业务，再考虑正式营业；下面的命令不会发布网站，也不会导入旧数据。

## 配置文件

后端读取项目根目录的 `.env`，模板为 `.env.example`。系统环境变量优先于文件里的同名配置。每行使用“名称=值”，注释单独放在上一行，不支持变量展开和行尾注释。

SQLite 数据库和上传目录的相对路径都固定以 StoreNet 根目录为准。默认数据库为 `data/store-net.db`，目录在首次初始化时创建；旧的根目录 `store-net.db` 不会自动使用。

首次运行前建议填写自己的初始管理员密码和登录签名密钥。门锁功能还不用时，保留 `TTLOCK_REAL_ENABLED=false`，加密主密钥留空即可。不要把真实密钥放到前端变量或版本管理中。

## 启动后端

在 StoreNet 根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8010
```

后端启动时会先初始化空数据库和管理员。已有相同结构的库会继续使用，不清空数据、不重置账号。只想提前检查数据库时，可以单独执行：

```powershell
.\.venv\Scripts\python.exe -m backend.initialize
```

如果提示数据库结构不一致，先停下来核对 `DATABASE_URL`。本版本不负责转换旧库，开发验证应改用新的空数据库文件，不能直接删除留有数据的旧库。

## 启动前端

在 `frontend` 目录执行：

```powershell
npm ci
npm run serve
```

页面默认位于 `http://localhost:8081`，开发服务器把 `/api` 请求转发到本机 8010 端口。后端和前端需要同时保持运行。

默认接口前缀为 `/api/v1`。前端需要改接口地址时，在 `frontend/.env.local` 中设置 `VUE_APP_API_URL`，值中保留这个前缀。后端 `.env` 不会自动传给前端。

## 检查与构建

后端语法检查在 StoreNet 根目录运行：

```powershell
.\.venv\Scripts\python.exe -m compileall -q backend
```

前端检查在 `frontend` 目录运行：

```powershell
npm test
node node_modules/@vue/cli-service/bin/vue-cli-service.js lint --no-fix
npm run build
```

构建结果位于 `frontend/dist/`，生成文件不等于已经部署。当前没有自动上传或发布步骤。

## 以后正式使用前

正式使用时保留配置检查：设置 `APP_ENV=production`，更换默认密钥和密码，限制跨域来源，配置 HTTPS 和可信反向代理。MySQL 需要提前创建本项目专用的空数据库，并单独验收；不要让程序连接 ChipsNet 或其他项目的数据库。

账号、权益、消费和门锁记录开始用于营业后，要定期备份数据库、上传文件及加密主密钥。涉及表结构变化时，另行制定经过验证的数据变更方案；当前初始化程序不会替你更新旧表。

存活检查为 `/api/v1/health/live`，就绪检查为 `/api/v1/health/ready`。它们不代替实际登录、计费、结账和真实门锁验收。
