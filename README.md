# StoreNet 门店管理系统

StoreNet 负责门店会员、区域计时和消费结账。会员可以自己上机、换区和查看费用，店长处理会员权益、定价与结账，管理员负责用户、角色和门店分配。

这份项目按**尚未部署、首次使用空数据库**准备。它独立运行，不读取 ChipsNet 或 gaowo 的数据；前端保留 Vue 2，后端使用 FastAPI 和 SQLAlchemy。

## 第一次运行

准备好 Python 3.12 和 Node.js 20 或 22。在项目目录把 `.env.example` 复制为 `.env`，按每项上方的中文说明填写。已经有 `.env` 就保留原文件，不要覆盖。

Windows 下依次打开这两个脚本：

1. `start_backend.bat`：安装后端依赖，首次启动自动建立空库和初始管理员。
2. `start_frontend.bat`：安装前端依赖，启动本地页面。

两个窗口保持打开，然后访问 [本地页面](http://localhost:8081)。后端接口文档位于 [接口文档](http://localhost:8010/docs)。后端默认仅监听本机，不会自动发布到公网。

默认新库保存在 `data/store-net.db`。项目根目录如果留有旧的 `store-net.db`，不会自动导入或删除。没有填写 `.env` 时，本地初始账号为 `admin`，密码为 `admin123@StoreNet`；填写配置后，首次创建账号以配置为准。修改配置不能重置已经存在的管理员密码。

## 现在有哪些功能

- 注册、用户名或邮箱登录、个人资料、头像和注册统计。
- 用户与角色权限管理，管理员分配门店，店长只管理所属门店。
- 会员管理，本金、赠金、次卡调整，以及不可编辑的权益流水。
- 多区域独立定价，自助或店长代上机，同店换区累计结账。
- 余额、次卡、现金或混合结账，消费记录与门店统计。
- 通通锁授权、选锁、一次性密码、发码记录、异常核对和授权自动续期。

不包含歌曲、成绩、公告、兑换码、在线支付和机器人联动。

## 计费规则

同一会员在本系统里只能有一笔进行中的消费。同一家店换区不结账：原区停止计时，新区接着计时，最后汇总费用。跨门店仍需先结账，不能混用不同门店的余额。

进入区域时保存价格快照，之后改价不影响这一段费用。返回同一区域且价格未变时，不重置当天该时段的封顶。计费按分钟向上取整，日间为 08:00—18:00，其余为夜间，跨时段和跨天分别计算。节假日价格字段已经具备，但自动日期判断目前只区分工作日与周末，不会自动读取法定节假日安排。

自助结账先用次卡，再用赠金和本金；目前一笔消费扣一次次卡，换区不额外扣卡。余额不足时保留消费和计时，需要联系店长处理。

## 数据库怎么处理

首次启动直接根据当前模型建表，不需要额外的数据库升级命令，也不再附带版本升级脚本。

之后重启不会清空账号、余额、消费或门锁记录。如果指定了其他项目的库、缺表的库或结构不兼容的旧库，程序会停止，不会擅自补表、改表或删除数据。开发中改过模型后，换一个新的空数据库验证即可；原库先保留。

这种方式面向目前尚未部署的阶段。将来有正式营业数据后，涉及表结构的修改要另行安排数据变更和备份方案，不能直接拿新代码覆盖旧库。

## 通通锁注意事项

真实调用默认关闭。普通计时和换区不需要门锁账号；要验证发码，先阅读[门锁接入说明](docs/门锁接入.md)。

自动发码区域必须先确认密码成功才开始上机或切换计时。换区发码失败时仍留在原区计费；结果待确认时不能重复发码。结账、取消申请都不等于撤销门锁密码。

相关代码经过模拟测试，不代表已经完成真实开门验收。首次正式使用前仍需检查 HTTPS、MySQL、并发限流、备份恢复和实体门锁。

## 目录说明

| 目录或文件 | 用途 |
| --- | --- |
| `backend/` | 登录权限、门店计费、门锁接口和首次初始化 |
| `frontend/` | 会员与管理页面 |
| `frontend/tests/` | 前端样式编译兼容与组件注册测试 |
| `data/` | 首次运行后生成的本地数据库，不提交版本管理 |
| `uploads/` | 头像文件，不会因初始化被清空 |
| `.env.example` | 每项都有中文说明的配置模板 |
| `docs/` | 运行、配置、门锁和维护说明 |

进一步阅读：[本地运行与配置](docs/本地运行与配置.md)、[开发与维护](docs/开发与维护.md)。
